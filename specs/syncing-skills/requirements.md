# requirements.md — syncing-skills

## 范围

本 spec 定义 **syncing-skills** 这个 skill 及其治理的机制：让**每个 agent 平台加载到的技能列表**与真相源保持一致。

- **包含**：分发目标的声明与生命周期（新增 / 下线）、技能的增加 / 改名 / 退役（技能内容由人提供，本 skill 不评审内容）、手工技能登记、跨端同步、对账与偏差排查。
- **不包含**：单个技能包的内容质量与写法（→ `authoring-skills`）、知识库正文（→ `maintaining-llm-wiki`）、脚本算法本身的重新设计。

## 术语

| 术语 | 含义 |
|---|---|
| 唯一源头 | GitHub 上的 `custom-skills` 仓库；自建技能只在这里发布 |
| 第二个来源 | `LLMWiki/skills/maintaining-llm-wiki` |
| 分发目标 | 某个 agent 平台加载技能的目录（如 `~/.dsh/skills`） |
| 分发清单 | `scripts/distribution-targets.json`，分发目标的唯一声明处 |
| 登记表 | `manual-skills.md`，手工技能的账 |
| 手工技能 | 人工放置、无仓库来源的第三方技能（在 Windows 目标是真实副本） |
| 对账 | 比对「声明」与「实际」，输出失败与提醒 |
| 失败 | 声明的东西缺失、损坏，或被顶替 |
| 提醒 | 声明之外多出来的东西（旧文件线索） |

## 需求

### R1 [普遍需求]
- EARS: 系统应把每个 agent 平台加载技能的目录声明在唯一的分发清单里，声明须含 `id` / `platform` / `relpath` / `expect` / `role` / `required` 六项。
- 验收标准:
  - Given 分发清单存在
  - When 读取任一目标
  - Then 六项字段齐备，`platform ∈ {win, posix}`、`role ∈ {junction, link, storage}`、`expect ⊆ {selfbuilt, mllw, thirdparty, manual}`、`required` 为布尔
- PBT 属性: 对任何目标 t，t 的六个字段都在合法取值域内，且 `id` 在账本的「所在面」词表里有对应 token。
- 优先级: 高
- 决策记录: 沿用现有清单（v3），本轮只增加自检，不改 schema。

### R2 [普遍需求]
- EARS: 对账应判定「声明的必须包含」，声明之外的条目只作提醒。
- 验收标准:
  - Given 某目标声明 `expect` 含 `selfbuilt`
  - When 该目标缺少某个自建技能
  - Then 退出码 1 并点名缺失项
  - When 该目标存在自建之外的东西
  - Then 退出码 0，并把多余项列为提醒
- PBT 属性: 对任何目标 t 与任何已声明名字 n，若 n 在 t 中解析不到（或解析到的不是本体系的链接），则退出码非 0；任何多余项都不改变退出码。
- 优先级: 高
- 决策记录: 见 `docs/adr/0003`。失败 = 声明的缺失 / 损坏 / 被顶替（STALE）/ 同名冲突；提醒 = 多余。

### R3 [事件驱动]
- EARS: 当任一 clone 里的技能目录集合发生变化时，系统应在两端各执行一次同步，使每个声明了 `selfbuilt` 的目标都指向新集合。
- 验收标准:
  - Given 仓库新增 `syncing-skills/`
  - When 两端各跑一次同步脚本
  - Then 每个声明 `selfbuilt` 的目标下都能解析到该技能且其 `SKILL.md` 可达
- PBT 属性: 对任何自建技能 s 与任何声明 `selfbuilt` 的目标 t，同步后 t/s 解析到唯一源头下的 s。
- 优先级: 高
- 决策记录: 沿用现有 `sync-wsl.sh` / `sync-custom-skills.bat`；分发维持人肉触发（已知接受风险）。

### R4 [状态驱动]
- EARS: 在对账运行时，系统应枚举本机用户家目录下所有**非空**的技能目录，并列出未在分发清单中声明者。
- 验收标准:
  - Given 某平台目录里有技能但未登记进分发清单
  - When 跑对账
  - Then 输出该目录及其条目数，且不改变退出码
  - When 目录为空
  - Then 不出现在输出里
- PBT 属性: 对任何非空技能目录 d，若 d 未在分发清单中声明，则对账输出包含 d；空目录永不出现。
- 优先级: 高
- 决策记录: 本轮新增；这是 09-03（ZCode 冻结快照）与 10-16（DSH 未登记）两次事故的直接防线。提醒级，不改判定。

### R5 [异常行为]
- EARS: 如果分发清单的字段缺失或拼错，或者账本的「所在面」出现未声明的 id，则系统应在对账开始时明确报错。
- 验收标准:
  - Given 把 `expect` 写成 `expected`
  - When 跑对账
  - Then 报错并指出字段名，不得静默把该目标降为「全部多余」
  - Given 账本某行「所在面」写了未声明的 id
  - When 跑对账
  - Then 报错并指出该 id 与行号
- PBT 属性: 对任何非法字段组合，脚本至少输出一条明确的错，且不产生静默降级。
- 优先级: 高
- 决策记录: 并入既有对账脚本，不新增可执行文件。

### R6 [普遍需求]
- EARS: 登记表里的每个手工技能都应能指出来源；当该名字存在于第三方锁文件时，来源应以锁文件为准。
- 验收标准:
  - Given 账本某行名字在锁文件里
  - When 入账或复核
  - Then 该行来源取锁文件的 `sourceUrl`
  - Given 名字不在锁文件里
  - Then 必须写明来源或标注「来源不详 + 日期」
- PBT 属性: 对任何账本行，要么有锁文件来源，要么有显式标注；不得留空。
- 优先级: 中
- 决策记录: 锁文件每条含 `source` / `sourceUrl` / `skillFolderHash` / `installedAt`，足以充当来源权威（对齐现状报告 N5）。

### R7 [事件驱动]
- EARS: 当某个 agent 平台开始加载技能时，系统应先在分发清单里登记该目标；当某个平台不再使用时，系统应先打印待清理清单再人工清盘。
- 验收标准:
  - Given 新工具在装且其技能目录非空
  - When 按流程登记
  - Then 清单出现该目标且对账覆盖它
  - When 下线一个目标
  - Then 下线预览命令打印该目标的路径与待清理清单、退出码 0，且不删除任何东西
- PBT 属性: 对任何目标 id，下线预览在删除清单条目之前可用；删除条目之后调用必须以「未知目标」失败而非静默成功。
- 优先级: 高
- 决策记录: 沿用 `--retire <id>` 语义；「先查证加载机制、再登记」的顺序不可省。

### R8 [普遍需求]
- EARS: skill 应以「目标 / 工作流 / 成功标准 / 停止规则」呈现，且易腐状态一律改为读取点。
- 验收标准:
  - Given `SKILL.md`
  - When 审阅全文
  - Then 不含具体技能名清单、不含目标数量或条目数量的断言
  - When 需要知道「现在有哪些目标 / 有哪些手工技能」
  - Then 正文指向分发清单 / 登记表 / 仓库 / 锁文件
- PBT 属性: 对任何会随体系变化而变的数字或名单，正文只出现读取点，不出现取值。
- 优先级: 高
- 决策记录: 唯一允许写死的集合是由脚本定义的判定类别名（失败 / 提醒两类）。

### R9 [普遍需求]
- EARS: 操作程序应只在 skill 里完整写一次，README 与合成页只保留各自的职责内容。
- 验收标准:
  - Given README、合成页、skill 三处
  - When 查某个操作步骤（如某同步脚本的调用方式）
  - Then 只有 skill 给出完整步骤，另两处只指路
- PBT 属性: 对任何操作步骤，完整描述出现次数恰好为 1。
- 优先级: 高
- 决策记录: 把合成页 v7.5 的「几何只在几何层写一次，其余层只指路」推广到文档与 skill 之间。

### R10 [事件驱动]
- EARS: 当人想了解「我的技能管理系统如何实施」时，README 应给出分发目标一览、四类来源的机制与落点、硬规则。
- 验收标准:
  - Given README
  - When 非作者阅读
  - Then 能回答：某平台的技能从哪来、改了怎么生效、加一个新平台要做什么
- PBT 属性: 对任何已登记目标，README 的目标一览里有它的一行（路径、角色、加载什么）。
- 优先级: 高
- 决策记录: 目标一览与技能表由生成脚本产出，避免人工枚举漂移（对齐现状报告 B1–B5 的成因）。

### R11 [异常行为]
- EARS: 如果要在工作区外的分发目标里删除条目，则必须先打印待删清单并获得人类确认。
- 验收标准:
  - Given 某目标里有 N 条待清理条目
  - When 执行清理前
  - Then 打印该目标的路径、条目清单与影响面，等待确认
- PBT 属性: 任何删除动作之前都有一条对应的清单输出。
- 优先级: 高
- 决策记录: 现有 `--retire` 已满足「只打印不删」；清理脚本沿用同一纪律。

### R12 [普遍需求]
- EARS: 本 spec 的完成应由机械门与独立复现共同证明。
- 验收标准:
  - Given 改动完成
  - When 跑机械门
  - Then 声明自检 0 错、两端对账退出码 0
  - Given 一个只读 skill、不向作者提问的 agent
  - When 在隔离环境（临时克隆 + 临时家目录）里执行五个场景（新增技能 / 改名 / 退役 / 新增目标 / 未登记目标发现）
  - Then 五个场景都能按 skill 独立完成，且与定稿产物逐项一致
- PBT 属性: 「能复现」只能由不看历史实现的独立复现证明，不能由作者自评。
- 优先级: 高
- 决策记录: 沿用合成页 v7.5 第 3 门（盲复现）；本轮改称「独立复现」，并明确隔离环境，避免在真机上产生副作用。
