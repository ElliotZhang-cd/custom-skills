# steering.md — syncing-skills

## 项目级规则（本 spec 的硬规则）

1. **不 commit、不 push**：所有改动落盘后由人确认再提交。
2. **不新增可执行文件**；不改脚本输出的中文字串；不改代码标识符与分发清单的字段名。
3. `specs/` 与 `docs/` 下**不得**出现 `SKILL.md`——自建技能的收集规则是「仓库根下含 `SKILL.md` 的目录」与 `find -maxdepth 2 -name SKILL.md`，放错位置会让规格文档被当技能分发。
4. **删工作区外的条目之前先打印清单**（路径、类型、时间戳）并等确认。
5. **术语用新词**（分发目标 / 分发清单 / 手工技能 / 登记表 / 硬规则 / 唯一源头 / 第二个来源 / 建链接 / 清死链接）；旧词只允许出现在对齐报告的旧→新映射与历史事故叙述里。
6. **操作程序单一出处**：完整步骤只写在 skill 里；README 与合成页只指路。
7. **易腐状态一律读取点**：正文不写技能名清单、数量、版本号；需要时指向分发清单 / 登记表 / 仓库 / 锁文件。
8. **技能内容质量不归本 spec**：内容是人的输入；写法评审转 `authoring-skills`。

## 全局规则（体系的硬规则，新词重述）

1. 自建技能绝不进入第三方 CLI 的锁文件；不对自建技能跑 `npx skills update`。
2. 第三方的唯一管理器是 `npx skills`；`openskills` 已弃用。
3. 编辑只发生在两个 clone 里；不编辑任何分发目标内的条目（那里全是链接或副本）。
4. 每个分发目标必须在分发清单里声明——登记了才算在管；不再使用的目标要显式下线。
5. 任何技能增删改后刷新派生表（技能表、目标一览）；该步骤**仅 WSL 可跑**（来源面在 WSL）。
6. 禁止无账拷贝：手工技能必须登记；Windows 的 `~/.agents/skills` 只能由 `npx skills` 写，不得手工放置（见 ADR-0004）。
7. 严禁向 junction 目标复制；目标的链接只由 `ensure_junctions.ps1` 增删。

## 偏离声明（都属显式接受，不是疏漏）

1. **方法论只用于本次构建**：用 EARS 写需求、用属性写验收、用检查点回退来构造本次改动；**skill 正文不移植** EARS / PBT / Hooks 这类仪式——它的读者是 agent，装不进可执行约束的仪式只会稀释真规则。
2. **接受机器绑定**：本 skill 明确服务这台机器的两个系统，因此偏离 `authoring-skills` 规范里「避免 Windows 路径」的要求，路径与平台差异直接写在正文与 `references/environment.md`。
3. **命名**：`syncing-skills` 为动名词，合 `authoring-skills` 的命名要求与仓库既有的 7 个动名词先例（此前候选 `sync-skills` 被否）。
4. **任务槽位映射**：本领域没有"移动端/无障碍"，六槽等价替换为 单点验证 / 全链验证 / 加载实证 / 多目标适配 / 人类可读性 / 验收。
5. **不建 `CONTEXT.md`**：术语改造取代独立词表——权威定义本来就在分发清单、登记表与脚本里，再造一份只会多一个要维护的真相。

## 跨平台共享

同一份仓库、分发清单、登记表被全部已登记目标共享；**规则与配置只有一份**，行为差异只来自各平台的加载机制（扫描根、rank、是否跟随链接、是否读 `~/.claude/skills`），这些机制细节写在分发清单对应条目的 `note` 里，README 只指路。

## 执行顺序

`T2 术语` → `T3/T4 脚本` → `T5 生成` → `T6 skill` → `T7 README` → `T8/T9 文档修复` → `T10 清理` → `T11 登记分发` → `T12 机械门` → `T13 独立复现`

理由：术语先定，避免写完再回炉；skill 必须在 README 与合成页之前成型，后两者才能"指路"到它；清理排在登记之前，以免把待清理项写进登记表。
