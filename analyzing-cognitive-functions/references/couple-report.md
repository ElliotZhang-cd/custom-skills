## 0. 定位与口径

- **目的**：读懂彼此差异 → 减少摩擦（诊断 + 药方），**只诊断模式、不判合分**
- **视角**：对称「你们 / A 和 B」，不预设读者方
- **机制**：每人先按 SKILL.md 六步定栈（00 速写卡承载各自的定栈结论），再逐功能对照；每条轴看「各自自比偏向」（A 用本人两端之比、B 用本人两端之比，互不换算）
- **语义**：大差值双面解读——摩擦 = 翻译成本，互补 = 分工资源；不把任何刻度当测量值
- **类型标签**：每人「定栈 X（仅供参考）」，MBTI 四字母不是身份证
- **数据完整性（硬前置，不可跳过）**：双人报告**必须双方数据齐全**（各 8 项功能分数）才能生成；只有一方数据时降级为单人报告 + 一节「从你这方看到的关系模式」，**明确禁止**分析、推测缺席另一方的任何心理特征
- **语言**：遵循 writing-style.md 全部规则——读者画像（无学术基础、受过良好教育的年轻人，直观形象一次读懂）、比喻收缩原则（§4.1）、裸代码彩色 = 功能身份、具体化形式多样、防伤害措辞、去 AI 味

## 1. 数据契约（换数据时改哪里）

所有图表由内联 `<script>` 从两个数据对象自动重算：

```js
const A = {Fi:...,Ni:...,Fe:...,Ti:...,Te:...,Ne:...,Se:...,Si:...};  // 甲方 8 分
const B = {Ti:...,Ne:...,Fi:...,Te:...,Ni:...,Si:...,Se:...,Fe:...};  // 乙方 8 分
```

1. 改 `A`、`B` 两个对象 → 雷达/四象限/四光谱全部自动重算
2. 光谱满偏系数 `K=256`：新数据最大 |log 比值| 明显不同则调 K，让最大落点贴近轨道端部
3. 四条轴的 L/R 定义在 `renderBeam` 挂载参数：`Ni–Se / Ne–Si / Ti–Fe / Te–Fi`（L = 第一个功能在左，两端标签 = 轴词对；轴序与单人 04 章统一，左端功能在前）
4. 四象限功能标签避让偏移表 `OFF`（8 个功能名偏移，手工定）
5. 象限分类表文字、光谱读数文案**需按新数据人工复核**（内部标定，**只用于选词、不写进报告**：比值≈1 说「几乎并肩」，1.2+ 说「一头明显靠前」，1.4+ 说「一头是主场」，2+ 说「另一头要专门使劲」；最大错位按 |log 比值| 排序定）

## 2. 章节结构（封面 + 00–05 + footer）

```
封面 hero      kicker + 定位句 h1 + lede 固定句 + 双人雷达叠加 + 图例 + 下滑提示
00 PORTRAITS   双方各**一行**速写（类型 + 栈序，尾注「详见各自的单人报告」）
               + 层次 1 一句：各自主导功能态度 = 各自最自然的意识模式；一方以该模式回应最顺，以相反态度运作最易误解
               + 「三处错位」预告段
               （不再重复六步定栈结论与能量画像——两人已有各自的单人报告，重复即冗余）
01 全局扫描     四象限矩阵（X=A 分, Y=B 分, 50 中线切四象限 + A=B 对角虚线）
               + 格位交叉表（A 的八个功能分别落在 B 意识层级的哪一格：优势/辅助/劣势/阴影）+ 共同盲区
               + 象限→含义分类表 + 边界一句（50 线是几何中点非及格线，**也不代表谁更强**）
02 四条轴      每轴：h3(Ni 预见 vs Se 体验 式) → 光谱条 → 自比读数(描述) → 摩擦点 → 互补点 →[场景块]
               + 四条轴小结表（轴/自比方向/摩擦等级/互补潜力）
03 亲密关系     吵架·谁先开口(A/B 内心戏各一 scene + 翻译建议) + 日常雷区(rel 定义列表) + 长期动力
               + 互为触发点（第 4/5/6/7/8 位互撞对照表，八格全覆盖）
04 怎么搭       层次 3 四问的**假设形态**（从格位推出，写成假设句 + 自查问题，不写成断言）
               + 三条协议(对着象限/光谱图各落一条, 定义列表式) + 个体化潜力（双方是否愿意收回投射）
               + 关系类型总结 + 「如果只记一句」scene
05 边界声明     bound-list 5 条(不判合分 / 分数会波动 / 摩擦=差异有互补、**但差异不保证成长、也可能就是永久误解** / MBTI 参考 / 关系是做出来的)
               + 附录 · 对照表(**各自偏向方向与深浅**，三大错位加粗) + 错位说明
footer         meta 行(双方代号 · 报告日期 · 数据来源) + 临床句（不判合分口径由 05 边界承载）
```

锚点 id：`hero`、`s0`–`s5`；章节标题 `00 · PORTRAITS`…`05 · BOUNDARIES`（衬线小字 letter-spacing .3em）。

> **待办（标签与样例同步）**：00 章内容已瘦身（不再重复单人的定栈结论与能量画像），"PORTRAITS" 这个英文标签与内容已不贴合；象限名/列名中性化后，`examples/mbti_sampleA_sampleB.html` 需同步重生成。lint 只校验 `s0`–`s5` 与固定句子串，改标签不影响 lint，但**样例必须先于交付更新**。

**互为触发点（03 章内固定块）**：对照双方的第 4/5/6/7/8 位撞上对方哪一格（八格全覆盖）。读法：一方最费力的一格恰是对方主场 → 摩擦是翻译成本、分工是资源；一方的第 8 位对上对方的高位 → 退行时最容易误读对方，写成预警 + 护栏，不写成宿命。

## 3. 视觉件规格（内联 JS 驱动 SVG，零外部依赖）

> 双人报告**用内联 `<script>` 数据驱动**（与单人静态 SVG 不同）：A/B 对象喂进脚本、图表自动重算（换数据即生成）。打印安全靠浏览器加载时渲染。功能身份色全报告常量，**与单人同一套**；人物编码：**实心 = A，空心/描边 = B**（颜色永远属于功能，不属于人）。

### 3.1 封面双人雷达
- 8 辐条序 `Fi,Ni,Te,Se,Fe,Ne,Ti,Si`（对置 1-5/2-6/3-7/4-8 仅为雷达排布，非四条轴配对）；viewBox 560×560，圆心 280，R=180
- 半径归一化（两人共用同一标尺，形状可比）：`r = R×(0.30 + 0.62×(v−min)/(max−min))`，min/max 取 16 个分的极值
- A 多边形：实线描边 + `rgba(31,95,102,.12)` 浅填充；B 多边形：虚线描边（`6 4`）、无填充、opacity .55
- 顶点圆点 = 功能身份色；外圈功能名同色（衬线 16 600，纸色描边光晕）；4 层参考环 + 8 辐条 #DCD6C8
- 图例（cover-legend）：「实线（浅填充）= A · 虚线 = B」+「重叠的部分是你们的共同底色，各自凸出的翅膀是互补的入口」

### 3.2 01 四象限矩阵
- X = A 分、Y = B 分，0–100 原始分线性映射；viewBox 560×560，pad 70
- 50 中线（虚线 #B9B29F）切四象限；对角虚线 = A=B 参考线（opacity .15），点到对角线距离 ≈ 差值
- 象限底色各 4% 透明（功能色）+ 四角角名（**中性化：只描述位置，不描述强弱**）：右上 = 两人都靠这一头、左下 = 两人都偏低、右下 = A 更靠这一头、左上 = B 更靠这一头
- 网格线 20/40/60/80；轴名「A 的分数 →」「B 的分数 →」
- 8 点：功能身份色实心圆 r8（opacity .85）+ 功能名标签（衬线 13 600 同色，按 OFF 表手工避让）
- 下方配「象限 → 含义」分类表（5–6 行：两人都靠这一头 / 两人都偏低 / A 更靠这一头 / B 更靠这一头 / 差距不大；A 贴线时增「贴线」行）+ 边界一句（50 线是几何中点非及格线，也不代表谁更强）。**「共同盲区」一词专留给 01 章格位交叉表**（范畴版：双方劣势落在同一领域）；象限左下角只是它的分数近似，不得复用该词

### 3.3 02 单轨光谱条（每轴一条，核心件）
- 形态：每轴一条水平轨道（x0=96→x1=544，y=88）；两端 = 该轴的两个功能（L 左 / R 右：功能代码 + 中文轴词）
- **落点映射（log 比值刻度）**：`offset = clamp(log(P[R]/P[L]) × K, −215, +215)` 像素，K=256；`x = 轨道中点 + offset`
  - 中点 = **平衡点**（两端相当 1:1），轨道上唯一标注的刻度（短竖线 #B9B29F，无文字）
  - 比值 > 1 落右侧（偏 R）、< 1 落左侧（偏 L）；对数刻度使 2:1 与 1:2 离平衡点等距
  - 满量程 ±215px ≈ log±0.84 ≈ 2.3:1
- 落点圆：A 实心 r9、B 空心 r8（bg 填充 + 2.6 描边）；颜色 = 各自偏向侧的功能色；A 标签在上「A · 偏X」、B 标签在下「B · 偏X」
- 两点间渐变带（左功能色→右功能色，30% 透明、rx6）：**纯视觉连接，不代表错位量**
- 读数口径：错位 = 「方向是否相反 + 各自偏向的深浅」；两点间距 ≠ 错位量。**无刻度数字、无 2:1/1:2 参考线、正文不出现数字倍数**（机制解释只在章引言；读数用 chart-note 一句）
- 每轴固定结构：光谱图 → 自比读数（chart-note，「方向相反/同向 + 各自偏哪一头、那头是不是主场」式**描述**，**不出现数字倍数**）→ 摩擦点 → 互补点 →（关键轴配）场景块

### 3.4 其余件
- 速写卡（portraits）：双列网格（≤600px 单列）；顶角 A/B 色块标签（A 墨青底白字 / B 纸灰底深字）、两个功能色点 + 学术名 + 栈位、一句话 desc、虚线上框内 MBTI 参考（标签走定栈结论，与单人同口径）
- 场景块（scene）：左 3px accent 竖线 + 小标签 b + 衬线正文（与单人同款线型件）
- rel 定义列表（relg）：A 的雷区 / B 的雷区（两键，斑马纹同款；**共同盲区已移到 01 章格位交叉表**，属意识层级交叉的事实，不在此重复）
- 边界声明（bound-list）+ 附录得分对照表 + footer（均与单人同款 CSS 类）

## 4. 文案口径

- 人称对称「你们 / A 和 B」；读数用**描述性语言**（「A 偏 Ni 预见：Ni 站在明处、Se 要专门使劲」；两侧接近时说「几乎并肩」），**不出现数字倍数，也不用分差绝对值**
- 禁区：不写「你们合不合 / 要不要继续」；摩擦一律表述为「差异 + 可操作解法」；不指责任何一方
- 机制解释（log、实心空心含义、50 线性质）只出现在章引言或边界句，不重复在图下（语言密度规则）
- 场景示例：吵架 / 选目的地 / 搬家等「一起做的事」对照两人内心戏 + 双向「翻译」话术（给 A 的话术、给 B 的话术对称给）
- **位置参照口径**：象限名与列名一律中性化（「A 更靠这一头 / B 更靠那一头」），**禁**「A 带 B / B 补 A / 谁更高 / 谁更强」式命名与结论；凡进入「更常用／更费力」层面的判断，只能用**各自内部的对比**（theory-spec §5.1 限制 1 及其位置参照例外）
- **投射清单口径（层次 3）**：skill 只有分数、没有访谈，四问一律写成**假设句 + 自查问题**（「你的第 4 位是 X，所以你可能最容易在对方的 X 上被吸引或被激怒——这一条请你自己核对」），**不得写成对来访者的断言**
- **摩擦的对称陈述**：摩擦既可能是「差异 + 可操作解法」，**也可能就是永久误解**；不得只写前半句（theory-spec §5.8：荣格本人对「互补即合适」持谨慎态度，差异本身不保证成长）

## 5. 伦理与边界口径

伦理口径由封面定位句、05 边界声明、页脚临床句共同承载；三条照录块必须出现（与单人 08 边界声明 + footer 同构）。以下三条为**照录、不得改写**（lint 双人口径校验其子串）：

### 5.1 05 边界声明「不判决」句（bound-list 内）

> · 八维模型是理解差异的透镜之一，**不是「你们合不合」的判决书**；它只能帮你看清「你们的认知模式放一起会怎样」，不能替代真实的相处。

### 5.2 05 边界声明收束句「不判合分」（bound-list 末条）

> · **最后**：如果这份报告让你们更愿意理解对方、少一些「你怎么这样」，它就有用了。关系是做出来的，不是算出来的。

### 5.3 页脚临床句（footer .disc 照录）

> 荣格八维 · 双人关系分析 — 基于你们俩的测评分数做的理论分析。本报告不构成临床诊断，也不判断「你们合不合」。数据是快照，不是宿命；理解是开始，相处才是答案。

（05 边界声明完整五条、封面 lede 固定句「荣格八维理论——看见你们俩的认知模式…」为照录基线，见样例；换数据/换人物时边界条措辞可按语境微调但「不判决 / 不判合分 / 不构成临床诊断」三层含义不得删。）

## 6. 与单人报告的口径差异（防串）

| 维度 | 单人 | 双人 |
|---|---|---|
| 图表实现 | 静态内联 SVG（手写坐标，lint 可数） | 内联 `<script>` 数据驱动（A/B 对象自动重算，lint 查脚本结构） |
| 人物编码 | 功能身份色 | 功能色不变 + **实心 = A / 空心 = B** |
| 核心叙事 | 你一个人的坐标（四条轴=天平） | 你们俩的错位与搭法（逐功能对照 + 四条轴光谱） |
| 判决红线 | 不构成临床诊断 | 另加**不判合分**（关系走向不由分数决定） |

## 7. 交付与命名

- 双人报告：`mbti_<代号A>_<代号B>.html` + 两份单人次 JSON（`mbti_<A>.json`、`mbti_<B>.json`）；保存路径同单人（默认 `~/Desktop/MBTI/`）
- 出双人报告时，两方各自也出单人报告：两份单人报告按基线（html-templates §1–§4）各自生成 + 各自 JSON；双人报告消费双方 JSON
- 咨询师备注（双人；与单人同口径，见 SKILL.md Phase 4）：作答质量（双方各一句）+ v2 分差提示（仅 -v2 时，双方各列变化>8 分的功能项）——对话内汇报，不写文件；缺席方禁止推测由 §0 承载，其余分析细节（类型/错位读数细节等）不进备注
