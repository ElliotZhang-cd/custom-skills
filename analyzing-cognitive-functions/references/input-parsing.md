# 输入解析与得分 JSON 规范

本地测试页 `8function_interactive.html`（70 题交互计分，百分制 0-100，题库与计分公式见 `soulstation_8function_70.json`）能产出两种数据格式。本 skill 的输入**仅接受这两种格式** + 用户另行提供的代号，不接受其他来源的裸分数。

## Contents
- §1 两种输入格式与解析规则
- §2 归一化与质量检查
- §3 用户代号规则（缺失 / 重复 / 漂移）
- §4 得分 JSON 输出规范

## 1. 两种输入格式与解析规则

优先级：**结果 JSON > 复制分数文本**。两种同时提供时用结果 JSON。

### 1.1 结果 JSON（`8function_results.json`，测试页「导出结果 JSON」按钮产出）

结构：

```json
{
  "metadata": { "source": "...", "version": "...", "scoring_formula": "..." },
  "answers": { ... },
  "scores": { "Se": 41.76, "Si": 37.12, "Ne": 41.86, "Ni": 65.54,
              "Te": 47.56, "Ti": 50.46, "Fe": 53.94, "Fi": 67.86 },
  "sorted": [ { "function": "Fi", "score": 67.86, "label": "内倾情感" }, ... ]
}
```

解析规则：
1. 取 `scores` 对象的 8 个功能键值（键名即功能缩写，顺序不依赖 JSON 内的排列顺序）
2. 校验：8 键齐全、每项浮点、0–100；缺键或超界 → 退回要求重发
3. 若缺 `scores` 字段但有 `sorted` 数组 → 从 `sorted` 恢复（每项取 `function` + `score`），并在咨询师备注中注明数据来源为降序表
4. `metadata` 与 `answers` 不参与分析，忽略

### 1.2 复制分数文本（测试页「复制分数」按钮产出）

格式（tab 分隔，功能名在左、分数在右，固定顺序 Se/Si/Ne/Ni/Te/Ti/Fe/Fi，两位小数）：

```
荣格八维评分结果
功能	分数
Se	41.76
Si	37.12
...
Fi	67.86
```

解析规则：
1. 按行处理；跳过标题行「荣格八维评分结果」和表头行「功能\t分数」（无法匹配 `功能代码+数字` 模式的行全部跳过）
2. 每行以首个分隔符拆分：分隔符 = tab / 全角空格 / 空格（含单个空格）/ 冒号；左段匹配 8 个功能代码之一（大小写不敏感），右段解析数字
3. 8 个功能全部解析到才算成功；缺任何一个 → 退回要求重发
4. **必须回显解析结果并经用户确认后才可继续**——顺序错则整份报告全错

### 1.3 容错规则（两种格式通用）

- 数字清理：去 `%`、`分` 后缀；全角数字/小数点转半角；空格剔除
- 解析后逐项校验 0–100 浮点，超界退回
- 解析成功的回显格式：8 行「功能代码 + 分数」+ 一句「请确认以上解析无误」

## 2. 归一化与质量检查

解析成功的分数归一化为固定顺序的字典：**`Ne, Ni, Fe, Fi, Te, Ti, Se, Si`**（浮点、0–100）。此顺序同时用于内部数据传递、得分 JSON 的 `scores` 字段、以及所有回显。

归一化后进入输入质量检查（规则见 `scoring-algorithm.md` §3）：
1. 完整性：8 项齐全、0–100
2. 十分制护栏：8 项全部 ≤10 → 不静默处理，反问确认
3. 扁平剖面检测：全距 <10 → 建议重测、所有推断降权
4. 作答质量模式：极端应答/敷衍 → 咨询师备注中警告

## 3. 用户代号规则

- 代号由用户在输入时另行提供（测试页产出的数据不含代号）
- **输入里没提供代号 → 停下反问一句**（如「请提供这位来访者的代号，用于文件命名（如 zyl）」），绝不自动编代号
- 代号要求：不用真名（隐私）；建议短小写字母/数字组合
- **目标目录已存在同名 `mbti_<代号>.json` 或 `mbti_<代号>.html` → 停下问**：「已有 mbti_\<代号\> 的旧报告。加 -v2 生成新版本，还是覆盖旧文件？」不擅自决定
- 用户选择 **-v2** 时：读取旧 `mbti_<代号>.json`，在咨询师备注中报告与本次分数 Δ>8 的功能项（重测波动的信号），然后以 `mbti_<代号>-v2` 命名保存新文件
- 双人场景：两个代号分别确认，冲突规则各自独立适用

## 4. 得分 JSON 输出规范

每次分析在生成报告 HTML 的同时落盘一份得分 JSON，与 HTML 同目录（默认 `/c/Users/elliot/Desktop/relations/MBTI/`），命名 `mbti_<用户代号>.json`（v2 时 `mbti_<代号>-v2.json`）。

```json
{
  "user_code": "zyl",
  "assessed_at": "2026-09-04",
  "source": "8function_interactive.html",
  "scores": {
    "Ne": 41.86, "Ni": 65.54, "Fe": 53.94, "Fi": 67.86,
    "Te": 47.56, "Ti": 50.46, "Se": 41.76, "Si": 37.12
  },
  "sorted": [
    { "function": "Fi", "score": 67.86, "label": "内倾情感" },
    { "function": "Ni", "score": 65.54, "label": "内倾直觉" }
  ]
}
```

字段规则：
- `user_code`：与报告文件名中的代号一致
- `assessed_at`：测评日期（YYYY-MM-DD）。用户主动提供了测评日期就用提供的；没提供则默认取报告生成日，并在咨询师备注中注明「assessed_at 为报告生成日，非实际测评日」
- `source`：固定 `8function_interactive.html`
- `scores`：8 键齐全、浮点、0–100，**顺序固定 `Ne, Ni, Fe, Fi, Te, Ti, Se, Si`**
- `sorted`：按分数降序排列的完整 8 项，`label` 用中文功能名（外倾感觉/内倾感觉/外倾直觉/内倾直觉/外倾思考/内倾思考/外倾情感/内倾情感）
- 双人场景：出两份单人次 JSON（每人一份）+ 一份双人 HTML，便于各自独立复用
- 落盘后用 Python 校验一次：JSON 可解析、`scores` 8 键齐全且顺序正确、与报告中的分数一致
