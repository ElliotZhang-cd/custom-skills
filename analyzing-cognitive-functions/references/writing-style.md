## 1. 语气总纲（最高优先级写作原则）

本总纲**高于本规范其余所有规则**，冲突时以此为准。

语气目标：**像真正为来访者着想、敢说真话的朋友**——平等、诚实、把来访者当作能承受真相的成年人，口语但克制、平实但不冰冷、不亲昵。**读者画像（Goal 级）**：没有心理学学术基础、受过良好教育、大学毕业的年轻人——语言要**直观、形象、一次读懂**；正文不出现「写给没有心理学背景」类定位语（该定位由全篇语气承担）。读完要能"看见"报告在说什么，而不是"看懂"一堆术语。

1. **冷静、直接**：先说结论再说理由，不绕弯、不堆情绪形容词。
2. **不说教、不奉承**：不用"你应该/你最好"指点，不用"你太棒了"夸奖；禁止安慰句式（"别担心"）、亲昵称呼、感叹号轰炸、轻慢承诺；成长空间用"现状 + 好处 + 代价 + 可以试着做"描述。
3. **好消息不夸大**：正向结果如实陈述，不拔高成"天赋异禀"。
4. **坏消息不回避**：该指出的短板、风险照说，用描述性语言，不回避也不灾难化。
5. **分析中立、建议利他**：分析从一种理论视角如实呈现，不宣称客观；提建议站在来访者利益和处境一侧。
6. **宁可不舒服也不误导**：宁可让来访者短暂不适，也不给虚假安慰或误导性结论；不确定的一律标"可能/推测"。
7. 用"你"指称来访者；多主动语态和具体动词，少堆抽象名词。
8. **直白、形象**：每个心理学概念都要翻译成普通人日常能直接感受到的动作或状态——能用画面、动作、日常物件说的，不用抽象词；宁可啰嗦半句，不留一个术语。

**器物比喻名受 §4.1 比喻纪律约束（收缩原则）**：正文以彩色代码与白话短对为主，学术名全称由表格承载；下表白描句保留为正典定义（天平图轴词、场景块取材于此）。

| 学术名（代码） | 白描（一句，可按语境微调措辞但不得改变含义） |
|------|------|
| 内倾直觉（Ni） | 把零碎的信息慢慢攒成一个判断，常提前"感觉"到事情会往哪儿走 |
| 内倾情感（Fi） | 心里有一把"什么重要、什么对"的尺子，决定多由它来做 |
| 内倾思考（Ti） | 喜欢把道理追问到底，看它说不说得通，习惯把问题拆到根上 |

引用规则（参考正文式）：
- **功能代码 = 身份**：正文可裸用代码（Fi、Ni……），以彩色衬线标识（`<span class="fn" style="color:var(--功能色)">`），颜色全书沿用（与第 1 章柱状图同款）
- **学术名首次全称**由 01 关键词总表、候选类型表与附录得分明细承载（「Fi 内倾情感」式）；正文叙述直接用代码或白话，无需逐次括注
- **双人报告口径**：双人正文与单人同款——彩色代码 = 功能身份；学术名全称由速写卡（「Fi 67.9（内倾情感·最高）」）与附录得分对照表承载；教学职责由单人报告承担，双人引入新概念时才补一句白描
- 全篇比喻（任何比喻）≤2-3 处，且只在比喻真正照亮概念时才允许使用

### 2.1 四条轴 → 大白话（讲法统一）

**先讲两大类（上位概念）**：**感知**＝直觉＋感觉，管你怎么接收信息（直觉跳着看：抓走向、抓重点、听懂话外音；感觉接着看：眼前、具体、此刻真实发生的）；**判断**＝思考＋情感，管你怎么拿主意（思考讲道理：逻辑、因果、对不对得上；情感看价值：什么重要、对不对得起人）。

**四条轴 = 类型推断所用的同四条轴**（`scoring-algorithm.md` §1.1/§2.3）：每条轴上两个功能互为对立面——一个是你顺手的，一个是你费力的。这不代表它们此消彼长，而是提醒：一项功能显不显，常取决于对面那个在不在场。

| 轴序 | 两端 | 白话定性（对照总表用） | 轴词对（天平图用） |
|----|------|----------------------|------------------|
| 一 | Ni–Se | 看远还是看眼前 | 预见收敛 ↔ 体验当下 |
| 二 | Ne–Si | 追新还是守旧 | 发散可能 ↔ 存档与熟路 |
| 三 | Fi–Te | 重价值还是重结果 | 忠于内核 ↔ 推进结果 |
| 四 | Fe–Ti | 顾人还是讲理 | 回应他人 ↔ 自洽建模 |

取舍标题四联（照录）:取舍一 · Ni 预见 vs Se 体验 / 取舍二 · Ne 发散 vs Si 存档 / 取舍三 · Fi 价值 vs Te 推进 / 取舍四 · Fe 氛围 vs Ti 逻辑。

- 取舍标题 = 短对（如「Ni 预见 vs Se 体验」），**不用昵称**（显影机/万花筒/守档人/推土机/建模师/翻译官等昵称层废弃）
- 天平读法（02 章引言照录）：「每条轴像一架小天平——分高的一端更重，沉在下面；两端接近时，天平放平。」
- **caption 四分支（固定文案，X 用功能色强调）**：双弱（两端实测分均列全维后三位）→「这条轴两头都偏弱——它不是你的主场。」；|差|≥12→「在这条轴上，更常露面的显然是 X。」；|差|≥5→「更常露面的是 X。」；|差|<5→「两者接近——这条轴没有明显的赢家。」
- 每条轴配「你是不是也这样」场景块一条（第二人称 ≤60 字、落在具体行为、不引入新结论；分数不进场景）
- **禁止**"梯队""断层""分数分层"这类排序叙事——八项分数各自独立累加，排序是人为的，相邻分差不构成理论单位。有意义的对比只有轴内两端（一条轴上的两个功能）。

### 2.2 八位置原型 → 大白话（理论模型，无实证常模）

一个类型是八个位置，从最顺手排到最费力。**前四位是"平时的你"，后四位是"压力下的你"**：

| 位置 | 原型名 | 大白话 |
|------|--------|--------|
| 第一位 | 英雄 | 你最自然、最拿手、最认同自己的部分 |
| 第二位 | 父母 | 你用来照顾别人、帮别人做事的工具 |
| 第三位 | 孩子 | 放松时才玩得起来、有点孩子气、也容易在这里受伤 |
| 第四位 | 灵魂 | 最费力、最想回避，但压力或亲密关系里会冒出来 |
| 第五位 | 对手 | 压力下冒出来跟你唱反调（和第一位相反） |
| 第六位 | 批评者 | 内心的挑剔声（和第二位相反） |
| 第七位 | 恶作剧者 | 最不听使唤、关键时刻最容易搞砸（和第三位相反） |
| 第八位 | 恶魔 | 压力最大时才出现、破坏性最强（和第四位相反） |

原型名（英雄/父母/孩子/灵魂/对手/批评者/恶作剧者/恶魔）**不进正文**；**例外**：「批评者 / 盲点 / 盲区」三个白话化称呼允许出现在候选类型表与附录得分明细的「角色」列（一眼能解、约定俗成），英雄/父母/灵魂/对手/恶作剧者/恶魔仅留在咨询师 reference。涉及此框架的表述声明"理论模型、无实证常模"。排位剖面图与类型栈打分表已随结构废弃，「角色」列 = 白话近似（如「主导 · 自我罗盘」「第二驱动 · 预见」）。

## 3. 硬性规则

- **R1**：功能代码可裸用于正文（彩色衬线 = 身份，见 §2 引用规则）；学术名全称由 01 关键词总表、候选类型表与附录承载
- **R2**：每条抽象结论必须有**具体化支撑**，形式不限：场景、对话、细节、反问、实例（见 §4.2 多样性要求）
- **R3**：凡推测内容必须带"可能/推测"字样；禁止"你就是""你一定""你肯定会"
- **R4**：描述功能差异用"更自然 / 更省力 / 更费力"，禁用"优势/劣势/强/弱"评价词
- **R5**：证据标签不进单人报告正文（ev-tag 已退出）；证据不再做逐章分级（见 SKILL.md Phase 4 精简决定）
- **R6**：报告正文**禁止出现**"咨询师""会谈""咨询中""建议你和咨询师讨论"等字样——报告只服务于来访者自我了解，不转介到外部关系
- **R7（术语零容忍）**：正文出现的每个心理学概念，必须翻译成普通读者日常能直接感受到的说法；术语只留在咨询师读的 reference 文件里。对照见 §6。这是正向规则——黑名单抓不住没列进去的词，只有这条总原则能保证不漏
- **R8（不给机制性解释）**：正文不解释分析是怎么做的——打分表怎么算、阈值怎么定、归一化顺序等，只给"怎么读"的结果；机制与算法留在 scoring-algorithm.md

## 4. 去 AI 味与去程序员味规则

### 4.1 比喻纪律（收缩原则，最高优先）

全篇比喻总数 ≤2-3 处。**比喻必须一眼解出**（读者能立刻想到实物或动作，不需要第二步解码）。

- **保留**（单步映射、日常语汇）：罗盘、翻译、雷达、磨合、排气阀、定海神针、黄灯、罢工
- **禁用记账系**（lint 强制）：税、电费、脚手架、基建、欠费、货币、预支账目——成本一律直说「多花力气 / 代价 / 消耗」
- **禁用暗房系**（lint 强制）：显影、底片、叠印——直说「信息归拢、互相印证 / 等答案成形」
- **禁用租客系**（lint 强制）：租客、房东、物业费、拖欠——直说「一直改天再说，直到身体罢工」
- **禁用机械系统系**（lint 强制）：引擎、变速箱、漏电——直说「顺利启动、持续发力」
- **昵称层废弃**：功能不用拟人昵称（显影机/万花筒/守档人/推土机/建模师/可能性雷达/氛围翻译/推进器/在场感/经验存档等），用轴词与白话短对（「跨阵营翻译官」为优势表定稿标题，豁免）

### 4.2 具体化形式必须多样
禁止连续多段以"比如："开头。交替使用：
- **场景**：有地点、动作、对话片段的小画面
- **对话**：引用可能真实发生的两句话
- **细节**：具体的、可观察的行为
- **反问**：让读者自己对照
- **实例**：直接举例，不必冠以"比如"

### 4.3 结构有详有略
禁止所有小节同构（每节都"定义→解释→例子"、长度均匀）。重点张力展开写，次要内容一笔带过。

### 4.4 句式
- 少用"不是……而是……"对仗句（全篇 ≤2 处）和排比
- 句子长短交错；允许短句单独成段
- 避免空转的连接词（"值得注意的是""总而言之""换句话说"）

### 4.5 绝对禁词（工程/IT/系统类）
**以下词汇及其变形，报告正文任何位置禁止出现**：

> 系统、架构、机制、流程、输入、输出、通道、带宽、负载、算法、迭代、反馈、模块、组件、审查、监控、容器、支架、空转、宕机、重启、调试、程序、数据库、接口、回路、闭环、触发器、运算、处理器、默认设置、双核、双引擎

**例外**：电量、充电、能量 允许使用

### 4.6 真实感
鼓励使用具体数字、具体时间、具体物件，而非泛指。

## 5. 深度规范

报告的分析单位是**功能之间的互动**，不是单个功能。

- **禁止清单式写法**：八个功能逐个点评、每个两三句
- **张力判断由 02 章四条轴承载**（天平图强弱 + 强端·代价表），不设独立张力小节；如出现跨功能组合类结论，写入强端·代价表或场景块，禁裸断言- **建议表每行 = 方向（护强/补弱）+ 具体做法（含频次/场景）**；「护强项回报 > 补短板」原则句为 06 章引言必备，章标题定稿「发展建议：先护强项，再帮短板省力」
- 全文目标 **2800–4000 字**（以参考体量为准）
- **分工原则**：图表承载分数与对比；正文只说倾向、含义与场景——数字不进正文（R8 姊妹条）
- **三级速读 = hero（定位句 + 雷达）→ 关键词总表 → 各章 h2/h3**；章尾由场景块（「你是不是也这样」/「写在最后」）收束；chapter-sub 与 pull 锐评已废弃

## 8. 防伤害措辞（来访者无心理学基础，且可能处于情绪脆弱期）

1. 永远不把分数与价值挂钩："得分靠后 ≠ 有毛病"
2. 单人报告已无成长环境章：推测属性由语言承担（「可能/推测」措辞与 07 边界声明）。双人报告的推测属性同由语言与 05 边界承担（不再逐条挂 ev-tag）

## 10. 语言件规则（单人 + 双人共用）

> 旧版组合卡 / 排位词（组合卡语境）/ .rel-label 标签式结构 / 锐评 / 题记 **已随旧结构废弃**；双人报告不再沿用组合卡/锐评/题记。有效条目（单双人都适用，双人专属件见 couple-report.md）：

1. **语言密度**：组件读法只允许一行说明（chart-note/图注），正文不复述组件用法（禁"下面这张表把…摆在一起"式旁白）；一处结论只带一个推测标记，禁止叠加免责；正文段 ≤3 句，场景对白除外
2. **一结论一画面**：每个抽象结论后跟一个"比如"级日常画面；没有画面改写到有画面为止
3. **分数旁白禁令**：禁平坦剖面/梯度类旁白（"八项都在 44–57""差距不大""没有一项掉队"式）——分数在正文的唯一叙述任务是判断哪头更常用、哪头更费力
4. **去 AI 味基线**（humanizer-zh 自查）：禁"这是一个温和的好消息"式概括抒情、禁"愿你……"祝愿腔、禁三段式排比堆叠、"不是A而是B"每段至多一次（全篇 ≤2）、破折号每段至多一个；改完大声读一遍
5. **比喻收缩原则**：见 §4.1（最高优先）——比喻必须一眼解出；记账系/暗房系/租客系/机械系统系禁用；昵称层废弃
6. **定位句（hero h1，单人口径）**：两句、每句 ≤10 字，嵌入前两位功能的白话定位词（如 Fi→内心价值、Ni→远见）；例：「用内心价值导航 / 用远见生活」；禁对仗金句腔、禁"不是A而是B"
7. **场景块**：小标签（`b`）+ 衬线正文；「你是不是也这样」每轴一条（第二人称 ≤60 字、落在具体行为、不引入新结论）；「写在最后」= 全篇收束；「三句值得直接背下来的句式」为 05 章收束件（三条可操作短句，可对话引用）
8. **兼容表规则**：互补（一句）/ 摩擦（成本措辞，禁评价词）/ 解法（可执行一句，含例句）；四行覆盖 执行型（Te/Si 强）/ 同类（与本人最强两项相同）/ 体验型（Se 强）/ 照顾型（Fe 极强）
9. **盲区表规则**：成本列 = 具体代价（不说"不行"，说"多花力气"）；「可以怎么做」列 = 可执行动作（含频次/场景，如「每周一次」「只做两分钟」）
10. **建议表规则**：每行方向（护强 ×2 + 补弱 ×2）+ 做法；补弱行的措辞 = 「给 X 用的办法：…」，禁"脚手架/托管/锚点"式说法（见 §4.1）
