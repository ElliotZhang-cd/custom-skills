# 成本视角用户研究（取证行为，不采信表态）

## Overview

验证用户是否真的接受产品：以用户愿意付出的真实成本（付费/时间/注意力/迁移/组织授权/心理安全感）为证据，识别"口头说好但行为不用"的失真。

## When to Use

**用：**
- 做用户访谈/客户调研，需要设计问题或解读回答时
- 用户/客户说了"挺好""有价值""以后会用"，需要判断可信度时
- 内测/共创/灰度结果"看起来不错"，上线前评估是否失真时
- 产品数据不差（有曝光/有打开）但用户价值存疑，诊断"用户是否真在场"时
- 老板/大客户/核心用户的强烈偏好需要判断"是否代表全体用户"时

**不用（Don't use for）：**
- 需要大规模量化结论（转化率、显著性检验）——统计问题，不是取证框架
- 纯数据指标解读（已有明确埋点数据）——成本框架是定性补充，不替代数据
- 用户表达明确功能缺陷（崩溃、报错、流程断点）——先修问题，不需要验证真实性
- 内部效率工具/一次性任务的反馈收集——成本收益不匹配

## 流程（按序执行，每步有完成标准）

### 步骤 1 — 把"接受"翻译成成本清单
用户愿意付出的成本类型 = **付费、时间、注意力、迁移成本、组织授权、心理安全感**。每种都是"买单"形式，从轻到重：愿意每天打开 < 愿意改变既有路径 < 愿意把真实业务流程交出来。
- 完成标准：列出用户当前已付出的成本类型与未付出的；区分"嘴上认可"与"成本付出"

### 步骤 2 — 检查离场信号
**离场不一定卸载**：企业软件里用户没有"离开"的自由，可以——不点、不看、不迁移、不推荐、不授权。功能还在页面上、入口还在首页里、后台还能看到曝光，但用户实际上已经离开了。
- 完成标准：判断用户是否处于离场状态；若后台有曝光但行为为零 → 输出"离场诊断"而非"活跃结论"
- 判停：确认已离场 → 输出结论，不继续追问"如何优化功能"

### 步骤 3 — 对口头反馈分层
用户的话要听，但不能照单全收。分层：
- **礼貌**："挺好"只是客气，信息量为零——听到恭维立即转问"那你现在具体是怎么处理的"
- **想象中的真话**：用户在想象场景给出的答案是真的，但只适用于想象场景。用户真心认为有价值的内容，当它突然出现在工作流中就是打扰——**用户没有撒谎，是两个场景里两个都真实的答案**
- **组织关系留余地**：面对供应商/平台方，用户天然委婉

判断标准不是说了什么，而是：愿不愿意多付一次成本、愿不愿意改习惯、愿不愿意让团队用、愿不愿意把真实流程交出来。
- 完成标准：每条口头反馈归入（礼貌/想象中的真话/组织关系/行为证据）

### 步骤 4 — 筛查三类失真样本
- **共创用户（内测玩家）≠ 真实用户**：投入了理解成本，会替产品补全意义、容忍不成熟、被叙事影响。"共创用户见过产品经理，普通用户只见到入口"——内测期验证过的"用户喜欢"，到真实市场可能验证为泡影
- **极端用户（老板/CEO）是真实用户但不是典型用户**：权力位置、信息密度、工作节奏异于大众；围绕他的反馈链路天然构成"人工个性化"，他不需要系统个性化，于是系统个性化的需求被低估。**"老板的身份认同，不是用户的目标"**
- **计划外用户是机会信号**：被具体价值吸引而非被叙事召唤的人更诚实；设计在目标用户处不成文、在另一群人处成立，可能提示真正机会不在原定方向

- 完成标准：判断反馈来源是否属于三类失真样本；对极端用户需求，明确回答"这个偏好是否代表目标人群的典型场景"
- 判停：反馈全部来自失真样本 → 结论标注"样本失真"，建议补充真实用户行为证据

### 步骤 5 — 对照预期与履约
用户对产品的预期来自名称、交互和宣传；**宣传越模糊漂亮，验收尺子越高**。用户拒绝的往往不是产品说出口的价值，而是没说出口的代价（"帮你整理工作"没说会改变已读状态）。
- 完成标准：列出产品对外承诺 vs 用户实际感知；找出"没说出口的代价"，判断代价是否大于收益

## 常见陷阱

1. **采信"想象中的真话"**：用户说的是真话，但只适用于想象场景——区分场景再采信
2. **共创失真**：共创用户会替产品补全意义、被叙事影响；共创结论必须标注"待真实用户验证"
3. **极端用户主导**：把权力位置用户的偏好当成全体路径——"老板的身份认同不是用户的目标"
4. **把"还在用"当成功**：曝光/打开不代表在场；离场是沉默的（不点不看不迁移）
5. **补丁替代不了根决策**：底层规则不改（如系统自动触发责任），交互补丁全部失效——收益成本错配的典型：承担成本的一方感知强烈（"我怕对方看到我已读不回"），受益方增量接近零
6. **正确问题死于节奏**：用户研究能指出方向，但组织节奏（每日可见交付）可能吃掉正确问题——研究结论要配上落地机制

## 边界

- **成本难以客观量化**（尤其心理安全感）——需要交叉验证；纯数据场景用统计
- **Mom Test 关系**：本 skill 是"成本视角"验证框架（含失真样本筛查），Mom Test 是访谈提问技法（问过去行为）——可组合使用
- **框架盲点**：企业产品语境（to B + 移动端 + AI 工作入口）下总结的失真模式，在 to C 消费产品中可能不同（冲动付费、社交压力等）；AI 产品的"信任成本"（模型幻觉、错误摘要）是新兴成本类型，尚未系统展开

## Verification Checklist

- [ ] 成本清单已列出（用户付出了什么/没付出什么）
- [ ] 离场状态已判断（不点/不看/不迁移/不推荐/不授权）
- [ ] 每条口头反馈已分层（礼貌/想象中的真话/组织关系/行为证据）
- [ ] 失真样本已筛查（共创/极端/计划外），极端用户需求已回答"是否代表典型场景"
- [ ] 预期 vs 履约差距已列出，"没说出口的代价"已识别
