# 建页阈值（先读）

- **建页**：实体/概念在 2+ 来源出现，或单来源但为该源核心主题
- **不建页**：passing mention（脚注级/顺带提及）——只链到已存在页，不新建

# 蒸馏规范（先读，优先级高于格式规则）

> 读者是你和 AI；页面自包含——不打开 raw、不依赖领域知识即可理解原文核心内容与逻辑。
> 检验视角：非相关领域但有高等教育基础的人能读懂。

1. **动笔前先画骨架**：
   - synthesis：画原文逻辑链——要回答什么问题 → 几步论证 → 结论。分组可重排、不必逐段对应原文，但因果顺序保留
   - concept/entity：画画像骨架——是什么 → 解决什么问题/为什么存在 → 怎么工作 → 怎么用/注意事项 → 意义/边界，五个面向都要有落点
2. **删除测试（每条要点过关）**：删掉它，读者还能理解核心结论（或这个对象）吗？不能删的才是核心。关键证据、数据、限定条件属于核心；次要例子与背景可略
3. **自包含检验**：出现领域黑话要么解释、要么类比（费曼风格可选，不强制）；页面第一行「一句话」是定义锚点——concept：它是什么 + 与相近概念的边界；entity：它是谁 + 干什么用；synthesis：这篇讲什么 + 为什么重要
4. **完稿核对（偏差汇报式）**：写完后对照原文（synthesis 逐段）或画像骨架（concept/entity 逐项），汇报一句：「来源有而页面无的核心内容：X；已补 / 判定为背景可略」

# 链接规则（横纵分类法，先读）

> 链接是导航不是装饰。建链前必答：这条链接属于哪个维度、哪类关系？答不出 = 不建。

| 维度 | 关系 | 含义 |
|------|------|------|
| 纵向 | 实例 / 前提支撑 / 延伸 | 层级：B 是 A 的实例、B 是理解 A 的前提、A 的机制在 B 深化 |
| 横向 | 同类 / 对比 / 互补 | 同级：同领域可比较、同一问题的不同方案 |

- 两条验证：① 关系分类答得出；② 跳转增益测试（读者跳过去获得实质理解增益）
- 双向回链仅限强关联；延伸类/叶子→枢纽的单向允许（录入 KNOWN_ONEWAY）
- 「相关」段 ≤10 条，超出砍最弱（数量是弱关联的暴露信号）
- 链接说明写"与本文的关系"，不写"对方是什么"

# 页面格式（当前约定）

> 这些是起点，不是终点。与用户共同迭代中。

## Frontmatter（当前约定）

```yaml
---
type: concept | entity | synthesis
tags: []                 # 不能为空
created: YYYY-MM-DD      # 首次创建日期，不随更新刷新
sources: []              # 与正文「来源」段对应（由 scripts/sync_sources.py 自动生成，请勿手写）
# entity 专用
entity_type: tool | plugin | service | company | guide | product | role
# synthesis 专用
coverage: "Agent 工程 / 环境配置 / Prompt 最佳实践"
# 可选
contested: true
status: incomplete | deprecated
---
```

> ⛔ 禁止字段：`source_count`、`updated`——派生物，真相源分别是 sources 数组和 git。曾两次根除又回潮（2026-06-24、2026-07-20），写入前确认不含。

> created = **首次创建日期**，页面后续更新不刷新；"最近更新"以 git 为准。（2026-08-12 lint：created 早于正文日期断言属正常，非矛盾）

> ⛔ 时间敏感断言（版本号、状态、"最新/当前"）必须带**日期锚点**——"截至 YYYY-MM-DD 为 vX.Y.Z"、"YYYY-MM 复盘"，禁止裸写"最新/当前"。（2026-08-12 lint 根除，Hermes v0.16.0 等曾裸写）

## 「一句话」规则（index 摘要唯一真相源）

- 每个页面必须有可解析的「一句话」引用块，写法二选一：
  - `## 一句话` 标题 + `> ...`
  - 或 `> 一句话：...`
- 长度 ≤ 100 字，超长必须重写。
- index 的简述列由 `gen_index_tables.py` 从「一句话」自动提取，禁止手工维护 index 摘要。
- 它同时是定义锚点，要求能独立理解。

## 来源段格式（当前约定）

| 类型 | 格式 | 示例 |
|------|------|------|
| raw 文件 | `[[wikilink]]`（带 .md 扩展名） | `[[raw/webpages/foo.md]]` |
| 外部 URL | `[描述](url)` | `[GitHub](https://github.com/...)` |
| 本地路径 | 反引号 | `` `~/.agents/skills/` `` |
| 原创观察 | 文字标记 | `原创观察` |

> ⛔ 禁止裸 URL（`- https://...`）和 md 链接写法（`- [](raw/...)`）；统一使用上表格式。
> 闭环：LLM 按此格式写「来源」段 → `scripts/sync_sources.py` 按此格式提取生成 frontmatter `sources`。

## 正文结构（当前约定）

### concept（概念定义）

常见结构：
- `# 标题`
- `> 一句话`（引用块，定义锚点，内容要求见「蒸馏规范」第 3 条）
- `## 要点`（3-6 条，可选分组）
- `## 相关`（≥2 条 wikilink）
- `## 来源`（raw/ 或 URL）

### entity（实体简介）

常见结构：
- `# 实体名称`
- `> 一句话`（引用块，定义锚点，内容要求见「蒸馏规范」第 3 条）
- `## 要点`（3-6 条，扁平）
- `## 相关`（≥2 条）
- `## 来源`

### synthesis（综合论证）

常见结构：
- `# 标题`
- `> 一句话`（引用块，定义锚点，内容要求见「蒸馏规范」第 3 条）
- `## 要点`（按原文逻辑链分组，每组 2-5 条）
- `## 相关`
- `## 来源`

> 💡 分组建议：按「蒸馏规范」第 1 条的骨架分组（论证结构优先于主题分类），例如"前提→机制→证据→瓶颈"。

## 文件命名

- kebab-case 英文，专有名词保留大小写。
- 使用稳定全称，不用易变缩写：`model-context-protocol`，而不是 `mcp`。
- 名称不含版本号：`hermes-agent`，而不是 `hermes-v0.16`。
- 消歧基于稳定概念边界：`graph-engineering` vs `graph-engineering-practical-guide`。
