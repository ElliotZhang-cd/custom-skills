# Query 查询流程

## 检索预算（公共前置）

按序执行，命中足够即停：

1. `grep -in "关键词" /mnt/c/Users/elliot/Documents/LLMWiki/index.md` — 表格过滤定位页面
2. `grep -rn "关键词" /mnt/c/Users/elliot/Documents/LLMWiki/wiki/ --include='*.md'` — 限定 wiki/ 目录精搜
3. 命中 >10 页 → 回 index.md 按标签收敛，再精读
4. `raw/` 不做全文检索；仅当需要溯源验证 wiki 断言时，按 index 登记路径精读单个文件
5. `log.md` 排除出检索对象（操作记录，非知识内容）

## 三分支

### 事实问答

- 步骤：定位页面 → 精读 → 直接回答
- 来源：回答标注 `[[wikilink]]`
- 回存：简单事实查询不回存

### 综合分析

- 步骤：多页交叉精读 → 对比/综合 → 标注全部 `[[wikilink]]` 来源
- 回存：多源综合/对比分析/新发现 → 简述摘要 → 用户确认 → 写入 wiki → 执行 Ingest 步骤 3 起的写入流程

### 外部产出（基于知识库制作 PPT/报告/总结等）

- 步骤：按检索预算取料 → 产出物
- 来源标注：产物内附来源页清单（如末页"内容源自 LLMWiki：[[prompt-engineering]] · [[general-prompt-writing-guide]] …"）
- 回存：产出不回存（产物即交付物）
- 发现的缺口/矛盾 → 告知用户 → 按 Lint 流程处理，不顺手改 wiki

## 边界情况（边界 + 建议 + 理由，≤3 条）

| 边界 | 建议 | 理由 |
|------|------|------|
| 页面内容重叠 | 互链保留双方，不合并 | 保留完整信息，连通性由互链承担 |
| 来源不完整/缺失 | `status: incomplete` + 标注「待补充」 | 不强下结论，给 lint 数据缺口扫描留钩子 |
| 矛盾断言 | 保留双方 + `contested: true` + 告知用户 | 不覆盖原则的显式化 |

其他边界情形按 Ingest「处理异常」执行（本表不重复列出）。

## 发现处理

查询中发现矛盾/过时/断链 → 告知用户 → 确认后按 Lint 修复流程处理。

## 验收标准

- ✅ 回答标注 `[[wikilink]]` 来源；外部产出含来源页清单
- ✅ 边界情形已按上表或 Ingest「处理异常」执行
- ✅ 规则未覆盖的情形 → 停下，向用户说明现状与选项，等确认后再继续
