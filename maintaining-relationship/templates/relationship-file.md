## 维护规则

- **只读不写，这套系统就退化成一次性分析。** 每次会话都必须写回。
- **别把它做成报告卡。** 一旦开始打分，就会开始隐瞒失败，记忆层随之失效。
- **画像条目带日期与锚点。** 无锚点的画像条目是标签，不是证据；新证据与画像冲突时更新并标灰旧条目。
- **判断不进本文件。** 档位、动作、去留只在 `README.md`。
- **一个关注点。** 想写第二条时，问自己哪条可以等到下个月。
- **过期不删。** 档案只增不减，读完成本高于收益，所以 §6 有上限；被推翻的条目标灰、标替代关系，保留移动痕迹。

## 术语（防同一概念多个名字）

- **动作**：带时间与场景、A 自己能做的具体行为；全系统任何时刻只有一个当周动作（入口 §1）。分层建议（即时/元原则/边界）不算动作。〔避免：建议、练习、行动项〕
- **锚点**：`消息 id` 或 `日期 + 短引`，把结论指回 `message.content` 原文；段落摘要不是锚点。
- **事实(高) / 推理(中) / 推测(低)**：证据三级；未标级别的结论视为事实级，是错误的默认。
- **单方来源**：仅有 A 的口述；可作"A 说过"的事实，不可作对 B 的判定。
- **日常层 / 结构层**：日常层=当下温度（分享/返场/亲密/摩擦）；结构层=是否在往前动（知情/风险说出口/第三人）。独立计分，不可抵消。〔避免：表层/深层——那指"事件表象/心理机制"，与去留无关〕
- **档位**：维持 / 观察 / 暂停 / 结束，由双层共同决定，硬红线一票否决。〔避免：阶段、状态——"修复期"是阶段，不是档位〕
- **硬红线**：越界隐瞒 / 蔑视常态化 / 系统性隐瞒需求 / 安全红线；区别于"底线"（底线是 A 的期待清单）。
- **正向条件**：已被原文验证的、能让 B 打开的具体情境；由模式二识别，模式四只引用。〔避免：优点、加分项〕
