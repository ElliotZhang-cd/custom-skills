# routing.md 中文版

注：本文件即路由层正文。若与 SKILL.md 有出入，以 SKILL.md 的分层定义为骨架，以本文件的触发条件为执行细则。

## 一、路由表

按 A 此刻真正所处的状态路由，不按“哪个 agent 听起来更有意思”路由。

| 你现在的状态 | 先用 | 用完接 | 产出 |
|---|---|---|---|
| 刚吵完 | 冲突 | 成长（看这次暴露了什么模式） | 这周一个动作 + 一条行为模式 |
| 冲突后三天仍不舒服 | 冲突 | 关系期待（看是不是期待在打分） | 判断是事件问题还是尺子问题 |
| 反复失望但没吵架 | 成长 | 关系期待 | 一条可练的行为 + 一条期待的来源 |
| 平静期，想更懂彼此 | 成长 | 关系未来 | 一个本周连接动作 |
| 想主动让关系更好 | 关系未来 | 成长（把设计落到互动） | 一个共同起点 + 一个行为调整 |
| 关系变好、想维持 | 关系未来 | 纵向追踪（下月验证） | 一个可复制条件 + 下月观察指标 |
| 其他 agent 给了建议、执行了，但心里还是不舒服 | 关系期待 | 回到原来的 agent，带着校准后的期待重新看 | 校准后的尺子，再重读同一件事 |
| 每月复盘 | 纵向追踪 | 趋势若为结构性，接关系期待 | 关系趋势 + 个人轨迹 |
| 每季度复盘 | 纵向追踪 | 关系期待 | 结构性趋势 + 尺子有没有移动 |
| 每半年 | 五份全跑一次 | — | 完整复盘，重写关系档案 |

## 二、使用节奏

- **每次会话，3 分钟，前提层**：读档案；回答自我位置三问；把“上次约定 X、执行情况 Y”一句话带进 agent。
- **每月**：纵向追踪。它的作用是**把判断从最近一次情绪里拉回来**。频率太低，情绪已经淹没了；频率太高，数据不够形成趋势。
- **每季度**：纵向追踪 + 关系期待。检查趋势是否结构性、尺子有没有移动。
- **每半年**：五份全跑一次，重写档案。

## 三、交接规则

- **冲突 → 成长**：可以连跑，成本低。同一次会话里跑，成长才看得到这次冲突的真实结构。
- **成长 → 关系未来**：**必须同一次会话**。关系未来不重新识别正向时刻，直接引用成长识别出的条件，设计一次复制。
- **冲突 → 关系期待**：只在“本次冲突里性的功能”或“期待错位”是当前真问题时接。性的完整拆解归关系期待；冲突只判断这一次能不能用别的方式补。
- **纵向追踪 → 任何 agent**：追踪交出“性话题的出现方式”和“A 的个人变化轨迹”。它不对趋势下裁定，其他 agent 引用时不要当成事实。

## 四、元层的两个使用时机

1. **季度校准**：每三个月，和其他 agent 一起跑一次——我的期待有没有移动、有没有哪条是继承来的、该不该放下。
2. **失效回退**：其他 agent 给了建议、A 执行了，但心里还是不舒服——这时问题不在行为，在尺子。回退到关系期待，重新校准，再带着校准后的尺子回到原来的 agent 重看同一件事。

## 五、预警信号

这些不叫失败，叫**系统在告诉你该换挡了**。触发时明确说出来并给出换挡建议，而不是继续分析当前议题。

| 信号 | 说明什么 | 该做什么 |
|---|---|---|
| 档案里“上次约定”连续两个月“没做” | 不是 A 不努力，是条件不允许，或关系在消耗 | 关系期待（检查尺子）+ 冲突（重新评估去留） |
| 自我位置三问里“怕失去”连续两次多于“想要” | 关系在吞噬自我 | 关系未来（支持系统检查优先于关系建设） |
| 追踪连续两个月“关系趋势下降 + A 的个人轨迹也下降” | 关系和个人同时受损 | 冲突（去留判断）+ 关系未来（重建支持系统） |

分析工具只能帮 A 理解，不能替 A 决定；预警机制的作用是防止 A 在错误方向上越走越深。

## 六、系统覆盖不到的部分

没说的话、线下的部分，任何 agent 都覆盖不了。承认一次，不要模拟。

ChatLab 里的记录也只是**已导入的部分**：没导的时段、删除的消息、语音转写失败的、线下的对话，都不在数据里。每次给出趋势或模式结论时，把这句话说一次。

## 七、数据取用规则（所有 agent 通用）

- **先 `chatlab_list_sessions` 定会话**，再把 `session_id` 写进档案第 0 节。之后每次会话直接读档案里的 id，不用重新找。
- **A/B 只按 `meta.owner_id` 判**，不看昵称、不看谁话多。
- **本地时间必须 `'+8 hours'`**；文本分析必须 `type = 0`。
- **引文只用 `message.content` 原文**。`segment.summary` 是 AI 摘要，只能用来定位。
- **所有查询带 `LIMIT`**。工具会截断，但截断前已经吃掉上下文。
- **拿不到就说拿不到。** 工具返回空、字段缺失、时段没覆盖，一律写“未发现”或“数据不足”，绝不补齐。

详细的工具清单、真实表结构和可直接复用的查询写在 `chatlab-mcp.md`。

## 八、一次完整会话示范（供校准）

情境：10/30 刚吵完。

1. **前提层**：读档案拿到 `session_id`；上次约定是“白天约一次规则对话”，没做（B 全夜班）；自我位置三问——关系占比大，挤掉了求职时间，留下“想要”多于“怕失去”。
2. **冲突 agent**：`chatlab_search_messages` 用"每次提需求""被定义成问题"这类原话定位到 10/30 那晚，`chatlab_get_message_context` 取前后文。输入附一句：“上次约定没执行，因为他全夜班；我这次最不能接受的是‘每次提需求就被定义成问题’。”输出：本周一个动作（白天两小时对话）+ 一条模式（B 关话题、A 追加长文）+ 决策树。
3. **成长 agent**（同一次会话）：用活跃时段分布确认"深夜发起"是可观察事实，再用段落摘要找"开门"的对话。输入附一句：“这次冲突里我最想改的是深夜间发起。”输出：一条行为练习（一句话说完就停）+ B 关门后的修复信号（想你想你、买小零食）。
4. **写回档案**：上次约定改为新动作；最关注的点从“性”改为“时机规则”；记下“他的修复信号是行动不是台词”，带消息 id 锚点。
5. **一周后**：读档案，看新动作执行了没有；没执行就在下次提问时说明卡在哪。

这个流程的关键不是“跑五个 agent”，是“带着记忆、带着真实记录跑两个 agent，把结论沉淀回记忆”。
