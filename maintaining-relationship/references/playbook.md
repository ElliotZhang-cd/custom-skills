# 分析手册：四种模式

模式一管单次冲突，模式二管两个人，模式三管时间，模式四管走向与决断。

**共用角色**：务实、直接、平等的分析师。对称标准——双方的伤害都写、修复都写；B 是关系的外部条件，不是分析靶子；关心 A 本人（情绪、支持系统、生活基本盘），不只关心关系。称呼：A 称"你"，B 称"他"或"B"。

**共用纪律**（不逐条重复）：证据分级、安全红线、数据纪律、男同语境、篇幅规则见 SKILL.md Constraints；框架用法见 psychology.md。本手册只写各模式特有的东西。

**交接**：同会话连跑时直接引用前一模式结论，不重新识别、不重新分析，引用注明来自模式几。**收尾判断与动作只在入口页写一次**——冲突类会话由模式一给动作，建设类由模式四给，校准类由模式二给。

## 模式一 · 冲突分析

**管**：单次冲突的结构、循环位置、危险度、本次读数变化。
**不管**：月度趋势（模式三）、画像全量更新（模式二；冲突里暴露的模式增量可顺手写回档案）。

### 取数

1. `chatlab_search_messages`：用 A 描述冲突的原话词 + 日期圈定定位，不整库搜。
2. `chatlab_get_message_context`：取前后文，拿到 导火索→升级→转折→结束 全链。
3. 需要当天全量原文用 SQL（chatlab-mcp.md 范式）；深夜判断必须 `'+8 hours'`，否则结论反转。

### 步骤

1. **结构链**：导火索、升级点、转折点（冲突方向改变那一刻）、结束方式，四者分开写；起点缺失标"空白，理解可能偏斜"；标这是第几次同构循环（纵向对比：重复/升级/改善）。
2. **深层转换**（依恋/EFT）：表面议题 vs 深层议题；A/B 各自的核心情绪、核心恐惧、依恋需求；谁追谁逃；一句加粗的引擎句，点出两人的什么需求/恐惧在互相触发。
3. **骑士与修复**（Gottman）：逐条标注四骑士，蔑视单列并进最危险模式（其余危险模式一句带过）；双方修复尝试与成败；转折点是否由修复促成。
4. **性的功能（限本次）**：本次冲突里性承担了什么（被渴望的证明/情感连接/排他确认/身体愉悦）、主需求、能否非性亲密替代。完整五层拆解归模式二。
5. **男同语境检查**（本次相关的 2–4 项，其余标"本次不适用"）：是否拿前任/软件/收入/外貌当武器；关系形式与规则是否清楚、双向同意；性健康沟通是否安全诚实非羞辱；无法定婚姻的现实隐患。
6. **判断**（四则，每则 1–2 句）：
   - A 的处境：情绪、支持系统、生活基本盘，先于关系议题；无红线也要明示"未发现"+需留意的非红线事项；B 的身心状态是关系外部条件，A 是协助者不是治疗者。
   - 滋养还是消耗；分歧性质（可修复/半结构性/结构性——半结构性必须写偏可逆还是偏不可逆、依据、还缺什么信息）；性欲问题给三路径（状态性/药物性/吸引力层面）与各自判定法。
   - B 关键表态的语境权重：真心承诺/止损/压力下表态。
   - 本次后双轴读数怎么动（psychology.md §五）。
7. **A 的旧伤权重**：反应强度里多少来自既往模式；无记录标"无法判断"。

### 输出骨架

1. 一句话带走（"如果只记一件事，这周做 X"，两句话内：动作 + 边界）
2. A 的处境（一段）
3. 结构链（表格 + 循环模式一句 + 第几次同构）
4. 深层引擎（A/B 需求与恐惧 + 循环位置；双方视角都在这节、不另设四视角节，但须用第一人称 + 具体场景或直接引语各写一句）
5. 骑士与修复（含最危险三模式：原文 + 为何危险 + 在循环中的作用）
6. 判断四则 + 语境权重
7. 分层建议：即时（≤3，可照读）/ 元原则（3–5，一句 + 一句解释）/ 边界约定（≤5）——**这些是证据层，不构成多个"本周动作"**
8. 双方行为对照（每人：做得好/做得不好，含原文与可替代做法）
9. 我可能错在哪（2–3 句）+ 待问问题（按"缺了就无法判断去留"排序，一问只问一件事；涉及去留必含三项现实核验，见模式四步骤 3）

### 模式止损

- 单方叙述要结论：可分析，逐条标"单方来源"，去留读数标"为时过早"。
- A 要求"直接告诉我该不该分"：给读数、代价对比、决策树（模式四），不替 A 决定。
- B 的关键环节无记录：标"未发现"，不拿上下文推测补全。

## 模式二 · 模式与画像

**管**：A/B 画像全量更新、互动开关、正向条件提炼、期待清单与校准。
**不管**：单次冲突裁决（模式一）、月度趋势（模式三）、未来设计（模式四）。

### 取数

1. 节奏：`chatlab_get_time_stats`（monthly）+ `chatlab_get_member_stats`，确认日常覆盖够长。
2. 开门对话：`chatlab_get_segment_summaries` 按话题取段，挑双方都接话、回合多的，`chatlab_get_segment_messages` 取原文。
3. 关门对话：`chatlab_search_messages` 搜 A 的触发词（"算了""随便""不想说了"）。
4. 期待句：逐个搜 `应该 / 不应该 / 正常 / 别人都 / 哪有 / 凭什么 / 如果爱我 / 真的喜欢一个人 / 在乎我 / 在乎的话 / 以前 / 前任 / 人家 / 他们 / 我妈 / 从小就`，记命中月份分布——"早期就有 vs 后期才出现"靠它判断。
5. 发起时机与单条长度：chatlab-mcp.md 查询范式（行为层事实）。

正向时刻必须来自真实对话原文；样本只有冲突片段时，正向条件降级"无法识别"。

### 步骤

1. **A 画像更新**（写回档案第 3 节）：沟通模式 ≥3（原文 + 帮 A 得到什么/代价，不判好坏）；触发点（词/场景 → 反应 → 背后需求）；依恋迹象（抗议/回避，对照三问自报）；修复信号（A 自己怎么表达"我还在"）；压力周期（A 的低余量时段）；稳定行为倾向（A 压力下的固定反应）；期待清单 ≥5 条（原文依据 + 来源标注：自己要的/原生家庭/前任/社会或圈内模板/来源不明——不确定写"来源不明"，不硬套；重点是看清来源，不是一律丢掉）；期待与 B 的错位（哪几条和 B 的实际表达方式冲突，附原文，不评判谁合理）；旧伤映射（期待是否来自既往被拒、被比较、被丢下的经验；无记录标"无记录，无法判断"）；性的五层功能完整拆解（被渴望证明/身体愉悦/情感连接/男性气质确认/排他确认：主需求 + 权重 + 主需求来源）；期待随时间的移动（早期/后期/减弱，附月份依据）。
2. **B 画像更新**（写回档案第 4 节；每条带锚点与证据级别，标"文本模式，不是读心"）：表达语法 ≥3；修复信号（"我还在"的方式；A 是否识别到、是否在等另一种信号）；压力周期（低余量时段——这些时段的冲突是资源问题，不是关系问题）；依恋行为迹象（回避/抗议，标推理）；触发点（从他的反应反推，标推理，不读心）；从行为推断的核心需求（标推理）；冲突循环位置（按议题，谁追谁逃）；稳定行为倾向（压力下的固定反应）。
3. **互动开关**：≥2 开门 + ≥2 关门（说了什么/对方怎么回/规律）。
4. **正向条件**：≥3 个自然连接场景（原文 + 可复制条件：话题/时段/状态/活动），只提炼、不设计。
5. **失效回退处理**（当本次是"建议执行了还是难受"的回退）：点名上次建议所依据的期待，检查是否继承来的标准；校准后带 A 用同一件事重读——结论变了问题在尺子，没变问题在事件。

### 输出骨架

1. 一句话结论（A 最该看见的一个模式 + B 最该理解的一个语法 + 最该放大的一组条件）
2. A 画像增量（表格：条目/锚点/级别）
3. B 画像增量（表格，同上 + "文本模式不是读心"注记）
4. 期待清单（表格：期待/原文/来源/帮 A 得到什么/代价/级别）+ 与 B 的错位一段（附原文，不评判谁合理）+ 旧伤映射一段（无记录标"无记录"）+ 期待随时间的移动一段
5. 性的五层功能拆解（主需求 + 来源）
6. 开关门表
7. 正向条件表
8. A 的本周行为练习（对应最值得调整的一个模式，A 自己能做、不要求 B 配合——这是本模式会话的动作位）
9. 我可能错在哪 + 待问问题（3–5 个）

### 模式止损

- 样本只有冲突片段：正向条件降级"无法识别"，标"样本偏差"。
- 期待句命中太少：明说"样本不足以反推完整期待"，不靠常识补。
- A 问"我的标准对不对"：不判对错，只区分来源与代价。
- 需要单次冲突裁决：转模式一。

## 模式三 · 现状与进程

**管**：月度/季度指标、趋势与波动、转折点、Sternberg 形状、阶段判断、A 的个人轨迹。
**不管**：单次归因（模式一）、画像更新（模式二）、去留裁定与设计（模式四）。

**前置**：至少三个月记录，不足则降级"初步观察"并先说明；附上次追踪结论，首次标"无纵向参照"。

### 取数

chatlab-mcp.md 第五节的 SQL 范式（月度量/发起占比/回复间隔中位数/时段分布/冲突代理）；哪些指标能精确算、哪些只能代理、哪些只能抽样判读，见其第六节，对 A 说清楚。

### 步骤

1. **指标表**：按月/季度 6 项——冲突频率（代理）、修复速度、蔑视/筑墙出现次数（抽样判读）、发起占比、亲密表达频率（代理）、回复间隔中位数；每格数值 + 级别，对 A 说清哪项是算的、哪项是判的。
2. **趋势判定**：每项 上升/持平/下降；**连续 3 个月同向才算结构性变化，否则是波动**。归因先扣干预：这是关系变了，还是上次约定/动作的执行效果？A 执行了动作之后的数据已被本 skill 改变（观察者效应）。
3. **转折点**：变化最明显的一月 + 当时生活事件 + 可能关联。
4. **Sternberg 形状**：激情/亲密/承诺当前配比与移动方向（psychology.md §四），与趋势数据并列。
5. **阶段判断**：一段话——现在在哪、往哪走、与档案读数是否一致。
6. **A 的个人轨迹**（单列，不混关系指标）：独立活动频率、非关系话题占比、自我语气变化；间接证据标推理(中)。
7. **性话题出现方式**：独立议题还是与工作/自我价值捆绑，按时间标注——供其他模式对齐，不裁定权重。

### 输出骨架

1. 使用提醒一句："这是趋势，不是判决。"
2. 一句话结论（变好/变坏/原地 + 2–3 个关键指标）
3. 指标表
4. 形状与阶段
5. 转折点
6. A 的个人轨迹
7. 双方对称观察（各一段）
8. 下次追踪建议（多久后再看、重点看哪两项）
9. 动作位：趋势出现结构性变化时给一个动作；否则入口页 §1 延续上次动作并注明

### 模式止损

- 只有冲突记录：亲密指标降级"不可靠"。
- "该不该继续"类要求：转模式四。
- 关系与 A 个人轨迹连续两个月同降：预警（见文末）。

## 模式四 · 未来与决断

**管**：双轴档位、情景推演、决策树、正向条件复制、共同起点、支持系统。
**不管**：重新识别正向条件（引用模式二）、重新算趋势（引用模式三）。

### 取数

1. **共同愿望**：搜意愿词（想去/想试/下次/以后/要不要），命中后用 `chatlab_get_message_context` 验证**双方都接过话**，并标注当时语气认真还是随口；A 单方提过的不算，写"未发现"。
2. **支持系统**：搜 A 提到的关系外人与事——结论只能是"记录里 A 曾提到 X"，标推测(低)，请 A 自己确认。

### 步骤

1. **双轴计分**：日常 0–5、结构 0–3，给两个数 + 一句话解释 + 档位；硬红线审查；结构连续两次复核仍 0/3 时点明观察档到期条件（psychology.md §五）。
2. **情景推演**（三条或选二，回答"关系未来有哪些可能"）：
   - 固化情景：当前模式持续不变 → 关系会变成什么样。
   - 改善情景：某个已识别的正向条件被放大 → 会走到哪。
   - 恶化情景：某个预警条件触发 → 会走到哪。
   每条附**观察信号**（之后看到什么数据/事件说明正在走这条）、**翻转条件**（出现什么证据此分支即作废，必须可检验）与**一年后的 A**（这个情景持续一年，A 本人会变成什么样——判断的是 A，不只是关系）。推演只有条件分支：禁单点预测、禁概率数字，开头标一句"个体关系预测无统计支撑"。
3. **决策树**："如果…那么…"三条，对应 A 最不能接受的三件事，每条附现实条件可行性；继续的代价 vs 分开的代价各一条（分开的代价具体到居住、经济、日常结构、支持系统）。**前置三项现实核验**（缺了就无法判断去留）：时间线对方是否认同（如"半年无性"他认不认）；身体/用药因素是否排查过医生；A 的独立住处与现金流。
4. **正向条件复制**：引用模式二识别的条件，设计一次 A 自己能安排的复制（时间/场景/做什么），不要求 B 配合、不设 KPI、不写"多沟通"。
5. **共同起点**：双方都提过没落地的事，最小可行版本（做什么/什么时候/花多少时间或钱）；日期 A 定，agent 给建议窗口，不替 A 承诺。
6. **支持系统检查**：除了 B 谁承接情绪、每周多少时间不在关系里、分开后谁在场；薄弱时"重建支持系统"升为第一优先，并建议 LGBTQ 肯定式咨询师。

### 输出骨架

1. 档位读数（两个数 + 档位 + 硬红线审查结果）
2. 情景表（2–3 条 + 观察信号）
3. 决策树 + 代价对比
4. 一个动作（复制/起点/支持系统三选一，A 自己能做）
5. 我可能错在哪 + 待确认（2–4 个）

### 模式止损

- 找不到双方共同愿望："未发现" + 建议 A 主动问一次，不编。
- 正向条件无来源（没跑模式二）：标"需先跑模式二"，复制步骤暂停，只出读数与情景。
- A 要求给关系定 KPI/打卡：不做，只设计"创造一次"。

## 预警信号（触发即换挡，说清是哪一个、为何优先于当前议题）

| 信号 | 说明什么 | 换到 |
|---|---|---|
| 约定连续两个月"没做" | 不是 A 不努力，是条件不允许或关系在消耗 | 模式二（尺子校准）+ 模式一（读数） |
| "怕失去"连续两次多于"想要" | 关系在吞自我 | 模式四：支持系统检查优先于关系建设 |
| 关系趋势与 A 个人轨迹连续两个月同降 | 双输 | 模式四（重建支持系统）+ 模式一（读数） |
| 结构进展连续两次复核 0/3 | 观察档到期条件 | 按双轴规则降档，或设硬到期日 |

## 一次完整会话示范（校准用）

10/30 刚吵完：读档案取 session_id 与三问 → 模式一（原话词定位当晚，取前后文）产出：动作（白天两小时对话）+ 模式（B 关话题、A 追加长文）+ 读数 → 同会话接模式二：活跃时段确认"深夜发起"是行为层事实，段落摘要找"开门"对话，产出：行为练习（一句话说完就停）+ B 的修复信号（返场、买小零食，行动不是台词）→ 写回档案（新约定、画像增量带消息 id 锚点）→ 一周后读档案看动作执行了没有，没执行就记卡在哪。

关键不是"跑满四个模式"，是**带着记忆、带着真实记录跑一两个模式，把结论和画像沉淀回记忆**。
