# 对账：怎么跑、怎么读、怎么排查

## 跑

```
python3 scripts/check_distribution.py                 # 对账（两端各跑一次）
python3 scripts/check_distribution.py --retire <id>   # 下线预览：只打印该目标的待清理清单，绝不删除
```

退出码：`0` 无失败 · `1` 有失败（或 `required` 目标缺失、清单自检不过） · `2` `--retire` 用法错误或未知目标。

覆盖范围随平台变：Windows 端只审 `platform: win` 的目标（posix 面在本机跳过）；WSL 端审全部——本机 posix 面 + `/mnt/c/Users/*` 上的 win 面。

## 判定分级

**失败**（退出码 1）——"声明的东西没到位，或被顶替了"：

| 标记 | 含义 |
|---|---|
| `[MISS]` | 声明的名字在该目标缺失 |
| `[BRK ]` | 声明的链接悬空（死链 / 死 junction） |
| `[STALE]` | 名字在、`SKILL.md` 也在，但**不是**指向本仓库/LLMWiki 的链接——被工具自建副本顶掉了 |
| `[EXTRA]` | 本体系僵尸：带管理标记但已不在声明里（改名/删除后的残留） |
| `[CONFLICT]` | 自建与第三方同名（触发不可判定，必须改名） |
| `[WARN] surface missing` | 目标目录不存在；该目标 `required: true` 时计入退出码 1 |
| 自检错误块 | 清单字段缺失/拼错、未知字段、`id` 重复或不在 `LEDGER_TOKENS`、账本「所在目标」含未声明 token |

**提醒**（不影响退出码）——"声明之外多出来的东西"，用来找旧文件：

| 标记 | 含义 |
|---|---|
| `[UNK ]` | 目标内既不在声明里、也无本体系标记（市场件、云管件、平台自带技能、旧副本） |
| `[NEW?]` | 家目录下**非空**、含 `SKILL.md`、却不在清单里的技能目录——「工具在用、体系不知道」的防线；空目录不报 |

为什么这样分：见 `docs/adr/0003`。代价是僵尸件不会让对账变红，只能靠人读提醒清单。

两个容易被误读的细节：

- `[UNK ]` 虽然不改退出码，却会**抑制该目标的 `[OK]` 行**（只有"无失败且无残留"才打印 `[OK]`）——所以"只剩 UNK 的目标"既不绿也不红。
- 技能删掉之后、同步之前，残留显示为**死链 `[BRK ]`**，不是 `[EXTRA]`；`[EXTRA]` 只发生在**仍能解析**的本体系条目上。

## 排查手册

| 症状 | 处置 |
|---|---|
| `[MISS]` 某个技能 | 跑对应端的同步脚本。仍缺则查该目标 `expect` 是否漏了对应来源、`role` 是否为 `junction`（补链只处理这一类） |
| `[STALE]` | 说明我们的链接被真实副本顶替了：Windows 跑 `ensure_junctions.ps1` 恢复；再查是不是工具自带管理器干的（它会再犯） |
| `[EXTRA]` | 本体系僵尸。确认源已改名/删除后手工删 |
| `[BRK ]` | 同步脚本会自动清死链；若清不掉，查源目录（仓库或 LLMWiki）是否还在 |
| `[UNK ]` | **不删**。逐条判断：市场件 → 留给工具自己管；旧副本 → 确认后清理 |
| `[NEW?]` | 逐条裁定：**在用** → 登记进清单（见 workflows「分发目标 → 新增」）；**不用** → 清理 |
| `[CONFLICT]` | 改名，不能共存 |
| 自检错误块 | 按报错逐条修清单/账本。**不要**绕过脚本手工建链接 |
| 对账全绿，但工具里看不到技能 | 加载机制问题：查该目标 `note` 里的扫描根与 rank；确认该技能是否 `disable-model-invocation: true`（那类只进 `/` 命令面板，属预期） |
| 工具面板里删过技能，随后对账报 `[MISS]` 一片 | 面板删除是目标级操作，会连带删掉本体系的链接与手工副本：先补链，再按 `manual-skills.md` 从另一个目标恢复手工技能 |
| 对账不绿，但同步脚本"看起来成功" | 已确认的两处：同步脚本把对账的非 0 退出码降级为警告（`|| true`）；技能表生成器崩溃时它仍会打印「完成」。**一律以对账输出为准**——这是已接受的待办，不是故障 |

## 残余风险（已接受，不是遗漏）

- 僵尸件、市场件、云管件只作提醒；清理靠人裁决。
- Windows 端的第三方池结构性为空（见 `docs/adr/0004`），所以 Windows 目标声明的是 `manual` 而不是 `thirdparty`。
- 工具自带管理器可以在两次对账之间物化或复活条目；`[STALE]` 与「未登记目标」是防线，但它们只在下次对账时说话。
- 装在同一系统里但不在清单里的工具目录不会被审（跨系统的同名工具目录亦然），只靠 `[NEW?]` 提醒。
- **发现机制只认名为 `skills` 的目录**：名字不同的工具技能根、以及仓库形目录，都不会被 `[NEW?]` 点名。
