# 对账判「声明的必须包含」，多出来的只作提醒

对账的判据是**子集**：某个分发目标声明了哪几类来源，这些来源的条目就必须都能解析到（缺 = 失败，退出码 1）；目标里多出来的东西（工具自带市场件、云管件、旧副本、未登记目录）一律只列出、不失败。

## Considered Options

- **实际必须等于声明**（2026-10-17 本轮先选后推翻）：任何多余项都算失败。会与工具自带市场机制长期对抗（workbuddy 的 16 个市场件、TRAE 会从云端复活退役技能），失败信号被永久噪音淹没。
- **只报告不判定**：全绿就没有意义——正是 v7 之前「用而不管」的成因。
- **子集 + 提醒**（选定）：失败信号只保留「声明的东西没到位或被顶替」，多余项作为**旧文件线索**输出给人看。

## Consequences

- **失败**：声明的缺失、声明的链接损坏、声明被真实副本顶替（STALE）、自建与第三方同名（CONFLICT）。
- **提醒**：未声明条目、未登记的非空技能目录、无 `SKILL.md` 的残留目录。
- **残余风险**：僵尸件不会让对账变红，只能靠人读「多余」清单发现。发现机制只做提醒，同样不阻断——这意味着"旧文件长期潜伏"是**被接受**的代价，而不是被解决的问题。
