# 自建、第二个来源与第三方都用链接分发；真实副本只留给尚未纳入 npx 的存量件

自建技能与 `maintaining-llm-wiki` 在所有分发目标上都是**链接**（WSL 两级符号链接 / Windows junction），指向 clone 与 LLMWiki 源目录。第三方技能在各**链接面**上同样是**链接**，指向该平台的 npx **仓库层**（WSL `~/.agents/skills`、Windows `%USERPROFILE%\.agents\skills`）。

分工是这一节的关键：**npx 只管仓库层（存储面 + 锁），平台层由同步脚本建链、由对账检查**。所以第三方改不改内容由 npx 决定，到不到得了某个平台由本体系决定，两件事互不越界。

唯一的例外是**尚未纳入 npx 的存量手工件**：它们在仓库层里没有条目可指，只能是人工放置的真实副本，登记在 `manual-skills.md`。一旦某个名字进了 npx 的锁，该面就应改由链接承载——对账会把仍占位的真实副本报成 `[STALE]`，销账后自动转严。

## Considered Options

- **第三方也用真实副本**（2026-09-03 – 2026-10-17）：当时 Windows 侧没有仓库层可指，只能复制；代价是副本会漂移、31 份手工副本要靠登记表点名。
- **全部用拷贝**（2026-09-03 v6.1 之前的 robocopy）：改名/退役后残留无人清理（08-21 列表僵尸事故），改动要两处三面复制。
- **全部用链接**（选定）：一个来源一份内容，改一处即全平台生效；跨平台差异只剩"仓库层里有哪些"，而那是各平台自己的锁说了算。

## Consequences

- **自建技能绝不进入 skills CLI 锁文件**：对自建跑 `npx skills update` 会把链接换成 GitHub 拷贝并覆盖本地修改。这是本决定的直接约束，不是一个独立决定。
- 严禁向 junction 目标 robocopy/复制（会把仓库复制进自己）。
- 第三方链接的目标是**本平台的仓库层**，所以要让某平台多一个第三方技能，得先在**那一端**跑 npx——不是改本仓库。
- 仓库层条目被 npx 移除后，指向它的链接成为死链，由同步脚本清掉（对账报 `[BRK ]`）。
- 工具自带的市场机制可以覆盖或顶替我们的链接——这正是 `[STALE]` 判定存在的原因。
